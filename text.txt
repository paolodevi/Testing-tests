Yes. In your case, NARX is actually a very natural method to try because you have multiple potential inputs and one output, and you suspect that the relationship is dynamic and nonlinear.

The MathWorks example you linked is also the newer dlnetwork/trainnet implementation, rather than the older narxnet workflow. Since you are using MATLAB R2023b, there is an important compatibility point: the exact code from that page is based on functionality introduced in later releases. 1. What we are trying to identify

Suppose your experimental data looks like

\[
u_1(t),u_2(t),\ldots,u_m(t)
\]

and you have one measured output

\[
y(t).
\]

A NARX model tries to learn something of the form

\[
\boxed{
y(t)=f\left(
y(t-1),\ldots,y(t-n_y),
u_1(t-1),\ldots,u_1(t-n_u),
\ldots,
u_m(t-1),\ldots,u_m(t-n_u)
\right)
}
\]

where \(f(\cdot)\) is a nonlinear neural network.

This is particularly interesting for your previous problem because you don't have to tell the model beforehand that the relationship is, for example,

\[
M = C_\alpha\alpha+C_q q+C_{\delta_f}\delta_f+\cdots
\]

Instead, the network attempts to discover the nonlinear mapping from the data.

The important distinction is that NARX is not just a static regression. It explicitly incorporates the history of the inputs and output. MathWorks describes exactly this structure in the example you linked. 


---

2. A MATLAB R2023b-compatible starting point

I would start with the classical narxnet implementation rather than trying to reproduce the R2025a example line-by-line.

Here is a complete starting script. I've deliberately made the parameters explicit so that we can later tune them systematically.

%% ============================================================
%  NARX SYSTEM IDENTIFICATION
%  Multiple inputs -> one output
%
%  MATLAB R2023b
% =============================================================

clear
clc
close all


%% ============================================================
% 1. LOAD YOUR DATA
% =============================================================

% Example:
%
% t  = time vector
% u1 = input 1
% u2 = input 2
% u3 = input 3
% y  = measured output
%
% Replace these with your actual variables.

load('myData.mat')


%% ============================================================
% 2. DEFINE INPUTS AND OUTPUT
% =============================================================

% Each input must be a row vector.
%
% Example:
%
% u1 = angle of attack
% u2 = flap deflection
% u3 = foreplane deflection
%
% y  = pitching moment

u1 = u1(:)';
u2 = u2(:)';
u3 = u3(:)';

y = y(:)';

% Put all external inputs into one cell array.
X = {u1; u2; u3};

% Target/output
T = {y};


%% ============================================================
% 3. SPLIT DATA INTO TRAINING AND TESTING
% ============================================================

N = length(y);

trainRatio = 0.70;
testRatio  = 0.30;

Ntrain = floor(trainRatio*N);

XTrain = cell(size(X));

for i = 1:length(X)
    XTrain{i} = X{i}(1:Ntrain);
end

TTrain = {y(1:Ntrain)};

XTest = cell(size(X));

for i = 1:length(X)
    XTest{i} = X{i}(Ntrain+1:end);
end

TTest = {y(Ntrain+1:end)};


%% ============================================================
% 4. DEFINE THE NARX MODEL
% ============================================================

% Number of delays
inputDelays    = 1:5;
feedbackDelays = 1:5;

% Number of neurons in hidden layer
hiddenNeurons = 10;

% Create NARX network
net = narxnet( ...
    inputDelays, ...
    feedbackDelays, ...
    hiddenNeurons);


%% ============================================================
% 5. PREPARE THE TRAINING DATA
% ============================================================

[Xs,Xi,Ai,Ts] = preparets( ...
    net, ...
    XTrain, ...
    {}, ...
    TTrain);


%% ============================================================
% 6. TRAIN THE NETWORK
% ============================================================

% Training function
net.trainFcn = 'trainlm';

% Train
[net,tr] = train( ...
    net, ...
    Xs, ...
    Ts, ...
    Xi, ...
    Ai);


%% ============================================================
% 7. PREDICTION IN OPEN LOOP
% ============================================================

[Y,Xf,Af] = net( ...
    Xs, ...
    Xi, ...
    Ai);


%% ============================================================
% 8. CALCULATE TRAINING ERROR
% ============================================================

Ytrain = cell2mat(Y);
Ttrain = cell2mat(Ts);

RMSE_train = sqrt(mean((Ytrain-Ttrain).^2));

fprintf('\nTraining RMSE = %.6g\n',RMSE_train);


%% ============================================================
% 9. CONVERT NETWORK TO CLOSED LOOP
% ============================================================

[netClosed,Xic,Aic] = closeloop( ...
    net, ...
    Xf, ...
    Af);


%% ============================================================
% 10. PREPARE TEST DATA
% ============================================================

[XTest_s,XTest_i,AiTest,TsTest] = preparets( ...
    netClosed, ...
    XTest, ...
    {}, ...
    TTest);


%% ============================================================
% 11. CLOSED-LOOP PREDICTION
% ============================================================

YTest = netClosed( ...
    XTest_s, ...
    XTest_i, ...
    AiTest);


%% ============================================================
% 12. CALCULATE TEST ERROR
% ============================================================

Ytest = cell2mat(YTest);
Ttest = cell2mat(TsTest);

RMSE_test = sqrt(mean((Ytest-Ttest).^2));

fprintf('Test RMSE     = %.6g\n',RMSE_test);


%% ============================================================
% 13. PLOT RESULT
% ============================================================

figure

plot(Ttest,'LineWidth',1.5)
hold on
plot(Ytest,'--','LineWidth',1.5)

grid on

xlabel('Time step')
ylabel('Output')

legend( ...
    'Measured', ...
    'NARX prediction')

title('NARX model prediction')


%% ============================================================
% 14. PLOT TRAINING PERFORMANCE
% ============================================================

figure

plotperform(tr)

grid on


%% ============================================================
% 15. DISPLAY NETWORK
% ============================================================

view(net)

The important point is that preparets is doing more than just formatting the data. Because the network has delays, MATLAB has to remove the initial samples needed to populate those delay states. This is exactly why preparets exists. 


---

3. Let's understand each important parameter

The most important line is:

net = narxnet(inputDelays,feedbackDelays,hiddenNeurons);

There are three things you need to choose.

inputDelays

For example:

inputDelays = 1:5;

means that the network sees

\[
u(t-1),u(t-2),u(t-3),u(t-4),u(t-5).
\]

If you have three inputs:

u1
u2
u3

the network therefore receives

\[
u_1(t-1),...,u_1(t-5)
\]

\[
u_2(t-1),...,u_2(t-5)
\]

\[
u_3(t-1),...,u_3(t-5).
\]

This is one of the parameters I would definitely investigate systematically in your case.

For example:

inputDelays = 1:2;

gives a very short memory.

inputDelays = 1:10;

gives a longer memory.

inputDelays = 1:20;

gives the network considerably more information about the past.


---

4. feedbackDelays

This is the autoregressive part.

For example:

feedbackDelays = 1:5;

means that the network uses

\[
y(t-1),y(t-2),...,y(t-5).
\]

So your network becomes approximately

\[
y(t)=f[
u_1(t-1:t-5),
u_2(t-1:t-5),
u_3(t-1:t-5),
y(t-1:t-5)
].
\]

This is why NARX is different from a normal feedforward regression.


---

5. hiddenNeurons

For example:

hiddenNeurons = 10;

means that the nonlinear mapping \(f\) is represented by a hidden layer containing 10 neurons.

You can think of this as controlling the complexity of the model.

Try something like:

hiddenNeurons = 5;

then

hiddenNeurons = 10;

then

hiddenNeurons = 20;

then

hiddenNeurons = 50;

and compare the test error.

Be careful, though: increasing the number of neurons does not automatically make the model better. Eventually you can overfit the training data.


---

6. Why do we train in open loop?

This is probably the most important conceptual point in the MathWorks example.

During training, we know the actual output:

\[
y(t).
\]

Therefore, instead of feeding the network's previous prediction back into itself, we give it the real measured previous output.

For example:

\[
\boxed{
\hat y(t)=
f(
y(t-1),
y(t-2),
u(t-1),
u(t-2)
)
}
\]

where the \(y(t-1)\) and \(y(t-2)\) are measured values.

This is called open-loop or series-parallel training. MathWorks recommends this approach for training NARX networks. 


---

7. Then why do we need closed loop?

When you actually want to predict the future, you don't know future \(y\).

Suppose you want

\[
y(t+1).
\]

You can calculate it from the known past.

But to calculate

\[
y(t+2),
\]

you need \(y(t+1)\).

You don't know the real \(y(t+1)\), so you use

\[
\hat y(t+1).
\]

Therefore:

\[
\hat y(t+2)
=
f(
\hat y(t+1),
y(t),
u(t+1),...
).
\]

And then:

\[
\hat y(t+3)
=
f(
\hat y(t+2),
\hat y(t+1),...
).
\]

This is the closed-loop configuration.

That is why we do:

[netClosed,Xic,Aic] = closeloop(net,Xf,Af);

MathWorks explicitly describes the open-loop → closed-loop workflow for multistep prediction.

Then the NARX model becomes

10. I would actually run a model hierarchy

Rather than immediately optimizing one enormous neural network, I recommend doing this:

Model 1 — Static nonlinear regression

\[
M(t)=f[\alpha(t),\delta_f(t),\delta_{fp}(t)]
\]

Model 2 — Input-memory NARX

\[
M(t)=f[
\alpha(t-1:t-n),
\delta_f(t-1:t-n),
\delta_{fp}(t-1:t-n)
]
\]

Model 3 — Full NARX

\[
M(t)=f[
M(t-1:t-n),
\alpha(t-1:t-n),
\delta_f(t-1:t-n),
\delta_{fp}(t-1:t-n)
]
\]

Then compare their prediction errors.

This gives you considerably more physical insight than simply saying "the neural network gives an RMSE of X."

11. There is another very important issue: your sampling frequency

The delays are specified in samples, not seconds.

Suppose your simulation has

\[
f_s=1000\ {\rm Hz}
\]

so

\[
\Delta t=0.001\ {\rm s}.
\]

Then:

inputDelays = 1:5;

means the model sees only

\[
1-5\ {\rm ms}
\]

of history.

But if

\[
f_s=100\ {\rm Hz},
\]

the exact same:

1:5

means

\[
10-50\ {\rm ms}.
\]

Therefore, before selecting the delays, we should look at your actual sampling frequency and the characteristic time scales of the dynamics.

For your aircraft problem this is particularly important because you may be trying to capture things such as short-period dynamics, actuator dynamics, aerodynamic lag, etc.


---

12. One more issue: normalization

The MathWorks example normalizes the training data using

\[
x_\mathrm{norm}
=
\frac{x-\mu}{\sigma}.
\]

This is important because your variables can have very different magnitudes.

For example:

alpha             ~ 0.05 rad
flap              ~ 0.1 rad
foreplane         ~ 0.05 rad
pitching moment   ~ 10000 Nm

Without normalization, the network's optimization can become poorly conditioned.

Crucially, the mean and standard deviation must be calculated using the training data only and then applied to validation/test data. The MathWorks example follows exactly this principle.
