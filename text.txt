Ripartiamo da zero e usiamo nomi coerenti per tutti i file. Lavoreremo in una sola cartella Linux, usando il compilatore e gli strumenti di Adams 2013.

La procedura sarà:

* Creare `gravity.adm`, il modello meccanico.

* Creare `gravity.f`, la subroutine Fortran.

* Creare `gravity.acf`, il comando di simulazione.

* Compilare e collegare la subroutine per ottenere `libgravity.so`.

* Lanciare Adams Solver e verificare i risultati.

Per ridurre i problemi di compatibilità, useremo il comando di compilazione delle user subroutines fornito da Adams, invece di inventare a priori un comando `gfortran` con opzioni di linking potenzialmente incompatibili. Adams supporta infatti la compilazione e il caricamento di librerie utente `.so` su Linux.

### 1\. Crea la cartella del progetto

Nel terminale Linux:

```bash
mkdir -p ~/adams_gravity
cd ~/adams_gravity
```

Tutti i file del progetto saranno in questa cartella.

### 6\. Eseguire Adams Solver

Dopo aver ottenuto `libgravity.so`, torna nella cartella del progetto:

```bash
cd ~/adams_gravity
```

Esegui il solver in modalità batch:

```bash
adams2013 -c ru-s gravity.acf exit
```

Se non esiste l'alias `adams2013`, usa il percorso completo del launcher, per esempio:

```bash
/percorso/Adams2013/mdi -c ru-s gravity.acf exit
```

Il comando `ru-s` avvia il solver; `exit` chiude il processo di comando al termine dell'esecuzione. La forma del comando può dipendere dagli alias installati.

Controlla quindi i risultati:

```bash
ls -lh gravity_run.*
```

Leggi in particolare il file `gravity_run.msg` per verificare se il solver segnala errori nel dataset o nel caricamento della libreria.

### Prima di lanciare tutto: due controlli importanti

Il collegamento dinamico e la compilazione dipendono dalla configurazione effettiva di Adams 2013. Per evitare che tu perda tempo su errori di ambiente, esegui questi comandi e conserva l'output:

```bash
which adams2013
which gfortran
```

```bash
find /percorso/Adams2013/solver \
  -iname '*gfosub*' -o -iname '*usersub*'
```

Sostituisci il percorso con quello reale della tua installazione. Con questi risultati potremo verificare la disponibilità del compilatore, individuare il template Fortran specifico della release e, se necessario, adattare la procedura di linking. Non darei per garantito che il template minimale sopra venga compilato senza modifiche nella tua installazione: il primo test deve confermare sia la firma di `GFOSUB` sia la sintassi del dataset.
